Kashtre Shared Unit Engine

Testing & navigation guide · Branch demo · For Inventory dual-run packaging
Share this with anyone verifying units, mappings, GRN conversion, and the Units console.

Important: This is not Kashtre super-admin home alone. Enter / browse a business first (e.g. Exquisite Test Life), then use Inventory screens.

1. Prerequisites

  1. App running locally (e.g. http://localhost:8000).
  2. In .env:
    UNIT_ENGINE_ENABLED=true
    Optional: UNIT_ENGINE_STRICT=false (keep false while dual-running; true = throw instead of silent legacy fallback)
  3. Run once:
    php artisan config:clear
    php artisan units:install
  4. Log in and open the target business (Inventory context).

Item form fields (this is the real packaging config)

  • Sale unit — stock / issue unit (e.g. Tab, Cap)
  • Order unit — pack unit from supplier (e.g. Box) — must differ from sale unit for packaging to matter
  • Sale units per order unit — factor (e.g. 100 tabs per box)

Manage Item Units only stores names (Box, Tab…). Reuse them from those dropdowns; do not create duplicate “Box” rows.

3. Recommended test path

Step A — Item units & mapping

  1. Open /item-units.
  2. Confirm Box (and Tab/Cap/Vial as needed) exist once per business.
  3. Check Engine mapping column: Box should show Mapped · BOX.
  4. For a custom name (e.g. Test Unit) still PENDING: click Map → pick a core unit → confirm.

Pass:

Badge shows Mapped · CODE. Creating a second “Box” for the same business is blocked.

Step B — Configure packaging on an item

  1. Open Manage Items → edit a Good.
  2. Sale unit ≠ Order unit (e.g. Cap/Tab vs Box).
  3. Sale units per order unit = 100.
  4. Save (engine syncs public IDs + packaging rule).

Pass:

Item saved. Under Units → Packaging rules, a rule appears (e.g. box → tab × 100).

Step C — Receive goods (main check)

  1. Inventory → create a GRN / receive goods.
  2. Add that item: qty (boxes) = 3, conversion = 100.
  3. Save.

Pass:

Sale units purchased = 300. Stock increases by 300 SUOM when GRN posts.

Fail:

Sale units = 3 with factor 100 → same sale/order unit, unmapped names, or engine off.

Step D — Orders / LPO (optional)

  • Order line with sale qty 300 → OUOM qty should be ~3.
  • Prefill GRN from LPO with remaining SUOM 300 → delivery qty ~3, conversion 100.

Step E — Units console smoke

  1. Catalog — search mg; optionally create a tenant unit.
  2. Composites — preview/save e.g. MG_PER_DL (mg / dL).
  3. Governance — activate / verify a tenant unit; check Audit.
  4. Policies — save a CLINICAL policy (analyte id + unit) if useful for demos.

5. Mental model (for the reader)

Item Units = name dictionary (Box, Tab).
Manage Items = which names + factor on each product.
Shared Unit Engine = canonical catalog + safe conversion (dual-run with legacy factor).
GRN / Orders = where conversion shows up in real stock/docs.
